**Scope and known limitations**

All 21 requested integration areas have executed representative cases. The 33 cases do not exhaust every role, form, browser state or exceptional path.

- INT-01 checks actual token authentication, role-aware API workspace data and representative forbidden endpoints for five roles. It does not execute browser redirects, React rendering, live MISD authentication or every role/endpoint combination.
- INT-02/03 check authoritative fixture relationships, current placement, invitation/approval mutations and API visibility. They do not exhaust multiple simultaneous placements, historical company changes or every section-assignment permutation.
- INT-04/05/06/13 exercise real clock actions, duplicate prevention, breaks, approval, correction ordering/audits, timezone display and downstream hours. The first-day absence and scheduled-afternoon defects remain. Overnight shifts, multiple breaks, geolocation and concurrent clock-ins are outside this selection. Student dashboard hours/day counts were checked; no nonexistent absence-counter field was invented.
- INT-07/08/09 verify review mutation, unrelated Faculty/Supervisor denials, overlap rejection and official-form/portfolio data. The Coordinator rule conflict and submitted-journal inclusion remain. FO-31 review status is present, but its serializer does not expose every reviewer field; the reviewer ID is checked in the authoritative journal. Browser PDF layout is not evidence here.
- INT-10/11 verify uploads and applicable requirements using controlled template sets, including a mixed status set and all-approved transition. This proves dynamic 1-, 2- and 4-item denominators, not every real catalog/template combination. The FO-24 regression checks six surfaces. Coordinator Student Summary does not expose the applicable denominator field that Faculty Summary does; compliance reports are checked separately.
- INT-12 combines real new-account registration, existing-account reuse/placement, rejection validation, mocked email, correct recipients and the prior role conflict. Email tests explicitly reject the test password and check messages/counts; they are not exhaustive token/secret scanners or real SMTP delivery tests. The role-conflict regression starts from a registered invite fixture to isolate downstream approval impact.
- INT-14/15 use the actual Faculty period-approval action and valid evaluator submissions. The existing form workflow checks FO-22/23/24/03 and exclusion of faculty_eval; the new draft case checks pending state. Live eligibility policy changes, all rating schemas and every result-visibility role are not exhausted.
- INT-16 reuses three real messaging flows for send/read, unauthorized thread access and reversible per-user archive. Attachment transport, realtime websocket delivery, rate limits and all notification combinations are not selected.
- INT-17 verifies authorized creation, invalid dates/Student role and the known unauthorized Coordinator persistence bug. The orphan is creator-visible, not Student-visible, and creates no attendees/notifications in this tested path. Director, calendar rendering and recurring meetings are not exhaustively tested.
- INT-18 triggers real appointment actions with recipient preferences and tests read ownership. Required transactional document/Supervisor notices follow their separate always-send policy; no universal notification deduplication claim is made.
- INT-19 is intentionally a broad portfolio assembly scenario: identity/HTE, journal, attendance, evaluation, saved essay/logo and cross-Student journal isolation. It samples duplicate section absence and does not exhaust all manual upload types or full frontend portfolio export.
- INT-20 compares report data using a legitimate stale stored-total fixture (0) against persisted validated attendance (8). It exposes that some reports bypass authoritative recomputation. Real-time report UI/PDF formatting and every aggregate/filter are not exercised. Journal/company/document counts and evaluation averages checked before the hour failure passed.
- INT-21 exercises implemented Admin staff activation/deactivation, login effects, role APIs and audit privacy. It makes no claim of live external MISD synchronization or all role-provisioning paths.

The baseline executes more existing feature tests, including some PDF/static checks. These are not promoted into selected scenario totals merely because their enclosing class name contains Integration. No screenshots, demonstration seed totals or successful builds are used as proof. The new observations are real test responses/persisted values, but schema-seeded demo records are not the authoritative evidence fixtures for the new scenarios.

No line/branch coverage percentage or load/reliability conclusion is claimed. Earlier concurrency failures remain documented in the prior pass and are not reclassified as integration results. Six application defects and two policy conflicts remain unresolved; the system must not be described as fully functional on this evidence.
